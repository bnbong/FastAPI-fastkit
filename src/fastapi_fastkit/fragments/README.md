# fastkit fragments

Jinja2 templates rendered by
`fastapi_fastkit.backend.project_builder.config_generator.DynamicConfigGenerator`.
They are the source of truth for every file the interactive `fastkit init`
flow generates.

The environment is built with
`Environment(loader=PackageLoader("fastapi_fastkit", "fragments"),
keep_trailing_newline=True, trim_blocks=True, lstrip_blocks=True)`, so every
fragment must end with a trailing newline and may use block tags on their own
lines without leaking whitespace.

## Layout

```
header.j2                 shared "Generated by FastAPI-fastkit" banner
main.py.j2                application entry point skeleton
main/imports/*.j2         import lines collected into main.py's import block
main/lifespan/*.j2        4-space-indented statements inside the lifespan handler
main/setup/*.j2           top-level statements placed right after `app = FastAPI(...)`
db/*.py.j2                database configuration modules (sqlalchemy, mongodb, redis)
auth/*.py.j2              authentication modules (jwt, fastapi_users, oauth2, session)
tasks/*.py.j2             background worker modules (celery, dramatiq)
features/*.py.j2          routers main.py mounts (tasks, cache, websocket, pagination)
logging/*.py.j2           structured logging + request-id middleware
migrations/*.j2           alembic.ini, async alembic/env.py, baseline revision, migrate.sh
tooling/*.j2              ruff / pre-commit / GitHub Actions / devcontainer / Makefile
docker/*.j2               Dockerfile / docker-compose.yml
test/*.j2                 pytest config and factory-boy fixtures
```

`main.py.j2` never hard-codes a feature. Import fragments are rendered,
deduplicated and sorted into isort-style blocks by
`DynamicConfigGenerator._build_import_groups()`, then handed to the template as
`import_groups`; `lifespan_fragments` and `setup_fragments` are `{% include %}`d
in order. Features therefore compose freely.

### Render context

Every fragment rendered through `_render_module()` receives the layout of the
project it is being generated into, so a fragment never hard-codes `src`:

| Variable       | Example              | Meaning                                  |
| -------------- | -------------------- | ---------------------------------------- |
| `pkg`          | `src`, `src.app`     | dotted import path of the app package    |
| `package_dir`  | `src`, `src/app`     | the same as a filesystem path            |
| `db_module`    | `src.config.database`| generated database module                |
| `auth_module`  | `src.config.auth`    | generated auth module                    |
| `app_module`   | `src.main:app`       | uvicorn entrypoint                       |
| `project_name` | `My API`             | raw project name (use `| tojson`)        |
| `project_slug` | `my-api`             | lowercase, hyphenated identifier         |

## Adding a new feature

1. **Catalog.** Add the choice to `FastkitConfig.PACKAGE_CATALOG` in
   `core/settings.py`, together with a member on the matching `*Choice` enum
   (a brand new axis also needs a `FeatureAxis` member, a `FEATURE_DESCRIPTIONS`
   entry, and — if it is multi-select — an entry in `MULTI_SELECT_AXES`).
   `DependencyCollector` walks `FeatureAxis` generically, so packages are
   picked up with no further changes.
2. **Prompt.** Add a `prompt_*_selection()` to `backend/interactive/prompts.py`
   and call it from `prompt_additional_features()`. Export it from
   `backend/interactive/__init__.py` and add a summary row in
   `selectors.confirm_selections()`.
3. **Fragments.** Drop the pieces you need into `main/imports/`,
   `main/lifespan/` and/or `main/setup/`. Lifespan fragments are indented by
   4 spaces; the other two are not. Register them in
   `DynamicConfigGenerator._main_fragments()`, guarded by the relevant
   `self._choice(...)` lookup.
4. **Standalone modules.** Add `<area>/<feature>.py.j2` and return it from
   `generate_feature_modules()` (or a sibling `generate_*_files()`) keyed by
   its project-relative path. `build_artifacts()` aggregates all of them, and
   `generate_all_files()` writes them — there is no separate write step to
   remember.
5. **Tests.** Add a case to
   `tests/test_backends/test_project_builder_config_generator.py`. The
   combination matrix there generates every artifact of every combination and
   asserts each `.py` file parses with `ast.parse`; `TestFeatureModuleGeneration`
   pins the individual feature to the code it promises.

## Rules

- Keep the `# fastkit:imports` / `# fastkit:routes` anchors in `main.py.j2`:
  `fastkit addroute` relies on them.
- Anything a fragment mounts (`app.include_router(x_router)`) must have a
  matching module in `generate_feature_modules()`. The matrix test fails
  otherwise — that check exists because the catalog used to offer selections
  that installed packages and generated nothing.
- Generated Python targets Python 3.12 and must be black-clean.
